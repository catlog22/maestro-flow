# v0.5.87

## Overview

v3 Runs gain lifecycle-contract drift governance: the contract hash is captured at Run creation, sealing a drifted Run is refused, and a new `run rebind` mutation rebinds a drifted Run to the current contract. `run check` and `run brief` now resolve contracts in diagnostic mode — reporting `contract_drift` and a structured `output_contract` report instead of throwing. The `help --json` catalog ships v2.0 with per-command option/positional specs and a preflight argv validator. This release also carries the Grok Build CLI adaptation, host-native Goal alignment, the knowledge-guard hook, and a broad set of Windows and KG-sync fixes.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.86...v0.5.87

## Highlights

- **Run contract drift governance**: `command_contract_hash` is snapshotted at Run creation; `run rebind <run-id>` rebinds a drifted Run to the current lifecycle contract; `run check` reports `contract_drift` (diagnostic-only) plus an `output_contract` declared/observed/missing/mismatches/unexpected report.
- **help --json catalog v2.0**: `option_specs` and `positionals` per command plus `validateArgvAgainstCatalog` — preflight validation with `UNKNOWN_OPTION`, `MISSING_VALUE`, `EXCESS_POSITIONAL`, `MISSING_REQUIRED`, `UNKNOWN_COMMAND` codes and edit-distance suggestions.
- **Grok Build CLI adaptation**: delegate, host assets, MCP, and Dashboard support.
- **Host-native Goal**: Goal aligns with the host `/goal` surface; Statusline enabled by default on install.
- **Knowledge-guard hook**: visible knowledge-gate signal before project file writes, with specs/knowhow direct-write warnings.

## Compatibility Notes

- `help --json` keeps `schema_version: 'help-catalog/1.0'` for existing consumers; the additive option/positional metadata is marked by `catalog_version: '2.0'`.
- `command_contract_hash` is absent on pre-snapshot v3 Runs; drift on such Runs is reported diagnostically and can be resolved with `maestro run rebind`.
- `run check` on a drifted Run is diagnostic-only: no Run, gate, or check-marker writes occur until the Run is rebound.
