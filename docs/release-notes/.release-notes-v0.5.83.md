# v0.5.83

## Overview

Hardens the search-index lifecycle and memory ownership end to end and
fixes the Kimi Code CLI install target. The local search daemon moves to an
authenticated protocol v2 (one request per connection, bounded payloads, an
explicit start/ready/drain/stopped state machine and owner-only descriptor
cleanup), the wiki indexer and embedding store gain lifecycle/ownership
guards with a much wider test surface, cold and warm index refreshes are
both made fast without missing newly created optional sources, oversized
legacy SQLite WALs are refused before migration opens them, and the
installer now targets Kimi's current `.kimi-code` config directory. `maestro-impeccable` is also
rewritten as a thin adapter that delegates to the installed Impeccable
skill instead of carrying a copied command surface.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.82...v0.5.83

## Highlights

- **Search daemon protocol v2**: the daemon descriptor becomes an authenticated identity (per-process `instanceId`, `maestro-search-daemon/v2` protocol tag) instead of a bare PID — stale or foreign descriptors are never trusted for search or shutdown, and only the owning process may delete its descriptor. Requests/responses are bounded (64 KiB in / 16 MiB out, 4096-char queries, 500 results) and the daemon drains gracefully instead of dying mid-request.
- **Lifecycle and memory ownership hardening**: spawn locking prevents concurrent daemon starts, descriptor cleanup is ownership-checked, legacy SQLite artifacts are refused when an oversized active WAL is present (instead of opening it blindly during migration), and the wiki indexer/embedding stores gained extensive new tests across the dashboard workspace and search surfaces.
- **Wiki index refresh performance and correctness**: synchronous bounded snapshotting restores cold-build latency, hermetic probes get larger certified time budgets and retry-safe Windows cleanup, and warm indexes now retain negative sentinels so newly created `project.md`, knowhow directories, and other optional sources invalidate immediately instead of remaining stale.
- **Kimi install target fix**: Kimi Code CLI skills/agents are installed to the current `.kimi-code` config directory (was the outdated `.kimi-code-cli`).
- **Impeccable command delegation**: `maestro-impeccable` no longer copies a routing/chain table; it adapts the installed Impeccable skill onto the canonical Session/Run lifecycle with the `--codify` extension loaded phase-wise.

## Compatibility Notes

- Search daemon descriptors written by older versions remain readable for status output but are never trusted for search or shutdown; a v2 descriptor is written on next start.
- Kimi Code CLI installs now land in `.kimi-code/`; existing `.kimi-code-cli/` installs are not auto-migrated (re-run install to refresh).
- `maestro-impeccable` now requires the Impeccable skill to be installed (fallback resolution documented in the command); the copied Maestro-owned workflow files are retired.
