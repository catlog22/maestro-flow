# v0.5.88

## Overview

`run check` becomes a completion preflight: it reports a structured `completion_preflight` block (ready flag, blockers, warnings, summary source) so a Run's completability — contract drift, missing summary, wrong status — can be inspected before `run complete` is attempted. The `help --json` argv validator gains an `INVALID_VALUE` code that enforces declared `choices` and a new `portable-path-segment` value constraint on `--request-id`. `scanOutputs` now honors declared `schema`/`role` from contract `produces` entries and surfaces mismatched `_meta` as strict errors.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.87...v0.5.88

## Highlights

- **Completion preflight in `run check`**: emits `completion_preflight` with `ready`, `blockers` (contract drift requiring `run rebind`, missing summary, non-running status), `warnings`, and `summary_source` (`argument`/`report`/null); accepts `--summary` to preflight a proposed completion summary.
- **Argv value validation**: `validateArgvAgainstCatalog` now emits `INVALID_VALUE` when an option value violates declared `choices` or the new `portable-path-segment` `value_constraint`; `--request-id` is constrained to path-safe segments (e.g. `run-control:0#abc` is rejected at preflight).
- **`run complete --verdict` constrained**: now a Commander `choices` option (`done` | `done_with_concerns`), so invalid verdicts fail at parse time.

## Compatibility Notes

- `completion_preflight` is additive on `run check` output; existing fields are unchanged. Drifted Runs report a rebind blocker instead of throwing.
- `INVALID_VALUE` is a new error code in argv preflight responses; consumers matching on `code` should treat it alongside `MISSING_VALUE`.
- Declared outputs whose `_meta` `role`/`schema` contradict the contract now fail strict validation rather than being silently repaired.
