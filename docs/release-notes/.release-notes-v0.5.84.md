# v0.5.84

## Overview

Introduces repository identity as a host-owned authority throughout Maestro's
workspace, agent, MCP, search, Spec, and knowledge surfaces. Knowledge content
now follows canonical metadata and repository-aware applicability rules, with
staged cross-repository promotion, read-only audit, and reviewed normalization.
Search and wiki indexing gain matching repository boundaries plus stronger cache,
daemon, embedding, snapshot, and Windows lifecycle behavior. The release also
moves UI codify to governed candidate staging and partitions the test harness
into normal, heavy, and Node lanes for reliable exhaustive release verification.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.83...v0.5.84

## Highlights

- **Host-owned repository authority**: a stable `.workflow/repository.json` identity is resolved and enforced across workspaces, delegation, MCP tool access, agent runners, team tools, and knowledge operations instead of trusting caller-supplied repository context.
- **Canonical knowledge lifecycle**: Spec and knowhow writers share canonical metadata and repository-aware loaders; run ledgers preserve evidence for staged cross-repository promotion; audit remains deterministic and read-only while normalization requires a reviewed report.
- **Repository-aware search and wiki indexing**: applicability metadata flows through CLI, hooks, dashboard indexing, and evaluation adapters, with improved cache invalidation, daemon cleanup, embedding disposal, snapshot performance, and Windows reliability.
- **Governed UI codify staging**: codification stages candidates, validates returned IDs, records failures, and links only after canonical promotion rather than predicting and writing final knowledge paths.
- **Reliable test and release lanes**: Vitest work is partitioned into normal and heavy suites, Node release tests remain explicit, process-global state is restored between suites, and lifecycle release probes gain stronger timeout and evidence validation.

## Compatibility Notes

- Repositories now persist a stable `.workflow/repository.json` identity. Local workflow runtime state remains ignored; the repository manifest is intentionally tracked.
- Knowledge and Spec operations distinguish destination and applicability repositories. Automation that previously supplied arbitrary repository IDs must use host-resolved context.
- Knowledge audit is read-only. Normalization is a separate reviewed mutation step.
- `npm test` now runs normal Vitest, heavy Vitest, and Node release-test lanes sequentially; focused invocations may continue to use the default Vitest configuration.
