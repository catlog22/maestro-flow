# v0.5.90

## Overview

Knowledge closeout now has one shared owner protocol: Review → Refresh → Present → Authorize → Execute → Verify. Completion coordinators review evidence-backed candidates and obtain explicit human approval before adjudication/publication; workers stage and hand off without repeating approval questions. The release also includes the merged KG sync fix for extensionless npm CLI symlinks.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.89...v0.5.90

## Highlights

- **Explicit publication authority**: fixed approved candidate IDs only; `-y`, machine recommendations, accepted decisions, and task completion never imply knowledge publication approval.
- **Single completion owner**: companion, session management, knowledge management, and run workflows load `ref/knowledge-closeout.md`, including an explicit Read fallback after context loss.
- **Independent completion/promotion gates**: zero candidates, rejection, deferral, and unresolved backlog permit otherwise valid completion. Session-source promotion validates immutable candidate/evidence snapshots and fresh reconciliation without requiring Session completion.
- **Reliable KG background dispatch**: resolve the real CLI entry before checking its JavaScript suffix, preserving background execution through extensionless npm symlinks.

## Bug Fixes

## Compatibility Notes

- This is a prompt-contract hardening release, not a new Runtime completion gate or a CLI schema migration.
- CLI `--all` semantics remain unchanged; the agent closeout protocol does not use it to widen human-approved selection.
- Rejected or deferred candidates remain in backlog; they are not fabricated as duplicates to clear review state.
- Existing source-specific reconciliation, immutable snapshot, and final-commit freshness checks remain in force.
