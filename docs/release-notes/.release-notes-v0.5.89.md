# v0.5.89

## Overview

Session/3.0 mutation ergonomics get a lean pass: identity flags gain safe defaults (`--participant` falls back to `--actor`, `--actor` to `$MAESTRO_ACTOR`, `--reason` to `cli:<command>`, `--request-id` to a deterministic idempotency key, `--session` resolves the unique open Session) while revision CAS fences stay mandatory. Retired v3 command stubs (`run status`/`done`/`list`, `session done`) now emit structured `run-response/1.2` error envelopes with replacement guidance instead of text-only failures, and the help catalog reports them as retired with replacement metadata. Installer copy paths skip `.git` internals and vendored `zvec-grep`, and overwrite read-only destinations on Windows instead of failing with EPERM.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.88...v0.5.89

## Highlights

- **Lean v3 mutation identity**: `addV3MutationOptions` consumers, `session open`/`migrate`, and `artifact republish` default `--participant`/`--actor`/`--reason`/`--request-id`/`--session` safely; `--expected-*-revision` CAS fences remain mandatory.
- **Structured retirement errors**: retired `run status`/`done`/`list` and `session done` stubs return `run-response/1.2` envelopes (`SESSION_SCHEMA_UNSUPPORTED`, `replacement_command`, `next_actions`) for `--json` callers, while stderr keeps a human-readable hint; `help --json` marks them `retired`/`deprecated` with `replacement`.
- **Writer-aware help routing**: bare `maestro --help`/`maestro help` resolves the workflow-root Session schema writer and registers the matching command generation instead of always showing the legacy surface.
- **Installer copy hardening**: `copyRecursive` and dashboard `copyDirectory` skip `.git` internals and honor per-component `fileFilter` (vendored `ref/zvec-grep` excluded); `copyFileOverwrite` clears the read-only attribute and retries once on EPERM/EACCES.
